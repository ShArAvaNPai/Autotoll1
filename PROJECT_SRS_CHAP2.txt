Chapter 2: Software Requirement Specifications (Pages 4-6)

2.1 Introduction
AutoToll AI is an advanced automated toll collection system designed to modernize the traditional toll booth infrastructure. By integrating computer vision, artificial intelligence, and cloud-based database management, the system automates vehicle identification and toll processing, thereby enhancing operational efficiency and user convenience.

2.2 Purpose
The purpose of this document is to define the functional and non-functional requirements for the AutoToll AI system. It serves as a guide for developers, stakeholders, and users to understand the system's capabilities, constraints, and operational workflows.

2.3 Scope
The scope of AutoToll AI includes:
- Development of a camera-based vehicle detection system deployed at toll plazas.
- Implementation of optical character recognition (OCR) to read license plates.
- Creation of a centralized database linking vehicles to owner wallets.
- Automated deduction of toll fees and generation of transaction logs.
- Provision of a web-based dashboard for administrative oversight and manual intervention.
- A user portal for vehicle owners to view history and manage funds.

2.4 Functional Requirements

    2.4.1 Real-time Vehicle Capture
    - The system shall interface with IP cameras to capture continuous video streams of oncoming traffic.
    - The system shall automatically detect the presence of a vehicle within a designated Region of Interest (ROI).
    - Upon detection, the system shall capture a high-resolution snapshot of the vehicle.

    2.4.2 Automatic License Plate Recognition (ALPR)
    - The system shall utilize the YOLOv8 object detection model to locate and crop the license plate from the vehicle image.
    - The cropped image shall be processed by EasyOCR to extract the alphanumeric characters of the license plate.
    - The system shall support diverse license plate formats, including standard and high-security registration plates (HSRP).

    2.4.3 Automatic Toll Deduction & Wallet Management
    - The system shall query the backend database to verify the vehicle's registration status.
    - If registered, the system shall check the linked wallet for sufficient balance.
    - The appropriate toll amount shall be deducted automatically based on vehicle class (Car, Truck, etc.).
    - Users shall be notified of the transaction status via the web portal or SMS (future scope).
    - Unregistered vehicles or insufficient funds shall trigger an alert for manual toll collection.

    2.4.4 Manual Review Queue for Low Confidence Cases
    - The system shall flag detections with confidence scores below a customizable threshold (default < 70%).
    - Flagged images shall be sent to a "Review Queue" accessible by the administrator.
    - Administrators shall have the ability to manually correct the license plate number and approve the transaction.

2.5 Non-Functional Requirements

    2.5.1 Performance Requirements (Latency & Accuracy)
    - Latency: The complete process from vehicle detection to toll deduction notification shall occur within 3 seconds.
    - Accuracy: The ALPR module shall achieve a detection accuracy of >95% for clearly visible plates in standard lighting conditions.
    - Throughput: The system shall be capable of processing at least 15 vehicles per minute per lane.

    2.5.2 Usability Requirements (Responsive Dashboard)
    - The user interface shall be responsive and accessible on desktop, tablet, and mobile devices.
    - The dashboard shall provide clear visual indicators (Green/Red) for transaction success/failure.
    - Navigation menus shall be intuitive, adhering to modern web design standards (Material Design / Tailwind UI).

    2.5.3 Scalability (Multi-lane Support)
    - The backend architecture shall support concurrent data streams from multiple cameras representing different toll lanes.
    - The database shall be designed to handle millions of transaction records without significant performance degradation.

    2.5.4 Reliability & Data Integrity
    - The system shall ensure data consistency, preventing double deductions for the same vehicle passage.
    - Critical data (transactions, user balances) shall be backed up regularly to prevent data loss.
    - The system shall implement robust error handling to recover gracefully from camera connection failures.

2.6 Software Requirements

    2.6.1 Frontend: React.js, Tailwind CSS, Vite
    - React.js: For building a dynamic and reactive user interface.
    - Tailwind CSS: For rapid, utility-first styling to ensure a modern look.
    - Vite: As the build tool for faster development and optimized production builds.

    2.6.2 Backend: Python, FastAPI
    - Python: The core programming language for backend logic and AI integration.
    - FastAPI: A high-performance web framework for building APIs with Python, enabling asynchronous request handling.

    2.6.3 Databases: SQLite (Local) & Supabase (Remote)
    - SQLite: For local caching and rapid retrieval of temporary session data.
    - Supabase (PostgreSQL): As the primary cloud database for user accounts, permanent logs, and authentication services.

    2.6.4 AI Tools: YOLOv8, EasyOCR, Google Gemini API
    - YOLOv8: State-of-the-art object detection model for vehicle and plate localization.
    - EasyOCR: Deep learning-based optical character recognition for reading text from images.
    - Google Gemini API: Leveraged for advanced data analysis and potential future enhancements in anomaly detection or natural language reporting.

2.7 System Architecture
The AutoToll AI system follows a client-server architecture:
- Client (Frontend): Captures user inputs and displays real-time data.
- Server (Backend): Hosts the API endpoints, runs the AI inference engine, and manages business logic.
- Database Layer: Stores persistent data.
- AI Service: A dedicated module within the backend that processes images asynchronously.
Communication between the frontend and backend is facilitated via RESTful APIs over HTTP/HTTPS.

2.8 Assumptions and Constraints

    2.8.1 Assumptions
    - Vehicles will reduce speed or stop briefly at the toll barrier (stop-and-go system).
    - License plates are legible and follow standard regional formats.
    - High-speed internet connectivity is available at the deployment site.

    2.8.2 Constraints
    - The system effectiveness is limited by camera resolution and mounting angle.
    - Extreme weather conditions (heavy fog/rain) may reduce detection accuracy.
    - Deployment is currently limited to a simulation environment and standard PC hardware.
    - Regulatory compliance with local data privacy laws (e.g., storing vehicle data) must be adhered to.
